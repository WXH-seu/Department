# 后台管理控制台开发计划

## 1. 建设目标

为系统管理员和部长提供独立的后台管理入口，用于查看全局运行情况、管理账号与组织、监督任务、查询审计日志。普通成员和组长继续使用现有工作台，后台控制台不替代日常任务页面。

第一版控制台重点解决当前管理功能混在单页、批量数据难查看、角色信息不完整、缺少服务端筛选与密码重置的问题。

## 2. 角色与入口

| 角色 | 控制台范围 |
| --- | --- |
| ADMIN | 全部控制台功能，包括账号角色、账号启停、密码重置、组织、任务、审计和系统状态 |
| MINISTER | 总览、人员目录、组织、全部任务和审计；不能授予 ADMIN/MINISTER、修改角色或管理高权限账号 |
| LEADER | 不进入全局控制台，继续在工作台管理自己负责的小组和任务 |
| MEMBER | 不进入控制台，只使用个人工作台 |
| GUEST | 不进入控制台 |

登录成功后根据角色显示“进入管理后台”入口。直接访问 `/admin` 时由前端路由和后端接口同时校验权限；前端隐藏按钮不作为安全边界。

## 3. 页面结构

### 3.1 管理总览

- 账号总数、启用/停用人数、各角色人数。
- 小组数量、尚未分组人数、没有负责人的小组。
- 任务总数、进行中、待验收、逾期和近七日完成数量。
- 最近登录失败、角色变更、账号停用等重要操作。
- 数据更新时间和手动刷新。

### 3.2 账号管理

- 按姓名、账号、角色和状态进行服务端搜索、筛选和分页。
- 查看账号角色、启用状态、小组归属和最近登录时间。
- 新建账号、修改显示姓名、启用或停用账号。
- ADMIN 可修改角色，但不能修改自己的角色或停用自己。
- ADMIN 可生成一次性临时密码；密码只显示一次，保存 BCrypt 哈希，并立即撤销该账号旧会话。
- 重置后的账号首次登录必须修改密码。
- 不提供硬删除账号，历史任务与审计记录始终保留。

### 3.3 组织与小组

- 小组列表显示成员数、负责人和未完成任务数。
- 创建、重命名小组，查看小组详情。
- 添加或移出成员，设置组内职务和小组负责人。
- 设置负责人时同步检查账号是否具备 LEADER 角色。
- 有未完成任务时禁止直接移出相关成员，并给出明确原因。
- 第一版不提供删除小组，避免破坏历史任务关系。

### 3.4 任务监管

- 按关键字、小组、负责人、状态、截止日期和逾期状态筛选。
- 服务端分页，默认按最近更新时间倒序。
- 查看任务详情、进度、评论、附件和状态流转记录。
- ADMIN/MINISTER 可创建任务、调整负责人，并处理待验收任务。
- 状态变更继续使用版本号做并发保护。
- 第一版不提供任务硬删除；确需作废时后续增加“已取消”状态。

### 3.5 审计与系统状态

- 按操作人、操作类型、对象和时间范围查询审计日志。
- 对常见英文操作码显示中文名称，同时保留原始操作码。
- 查看后端健康状态、数据库连通状态、附件目录可写状态和应用版本。
- 系统状态只做只读检查，不在网页中执行数据库启停、备份恢复或服务器命令。

## 4. 后端改造

### 4.1 管理接口

在保留现有 `/api/v1` 接口兼容性的前提下，新增 `/api/v1/admin` 管理接口：

| 接口 | 用途 |
| --- | --- |
| `GET /admin/overview` | 总览统计 |
| `GET /admin/users` | 账号搜索、筛选和分页 |
| `POST /admin/users` | 创建账号 |
| `PATCH /admin/users/{id}` | 修改姓名、角色或状态，按权限限制字段 |
| `POST /admin/users/{id}/reset-password` | 生成一次性临时密码并撤销旧会话 |
| `GET /admin/groups` | 小组统计列表 |
| `GET /admin/groups/{id}` | 小组详情与成员 |
| `PUT /admin/groups/{id}/members/{userId}` | 设置成员关系和组内职务 |
| `GET /admin/tasks` | 全局任务筛选和分页 |
| `GET /admin/tasks/{id}` | 任务、评论、附件和流转详情 |
| `GET /admin/audit` | 审计日志筛选和分页 |
| `GET /admin/system` | 只读系统状态 |

列表接口统一返回 `items`、`page`、`size`、`total`，最大每页 100 条。所有查询使用参数绑定，排序字段使用固定白名单。

### 4.2 数据模型

新增数据库迁移：

- `app_user.must_change_password`：首次登录或管理员重置后为 `TRUE`。
- `app_user.last_login_at`：登录成功后记录最近登录时间。
- `task_status_event`：记录任务状态、进度、操作人和变更时间，供控制台展示完整流转历史。

现有成员表中的手机号和一卡通号继续不入库。控制台不展示系统当前没有保存的个人信息。

### 4.3 安全约束

- `/api/v1/admin/**` 默认只允许 ADMIN/MINISTER，再由每个写接口执行细粒度权限判断。
- 只有 ADMIN 可以赋予 ADMIN/MINISTER、修改角色或重置高权限账号密码。
- 禁止管理员修改自己的角色、停用自己或重置自己的密码；本人继续通过“修改密码”功能操作。
- 密码重置响应只返回一次临时密码，不写入日志和审计详情。
- 账号角色、状态、密码和组织关系变化后递增 `session_version`，使旧会话立即失效。
- 新增账号、角色变更、密码重置、启停、成员关系和任务监管操作全部写审计日志。

## 5. 前端改造

- 引入 Vue Router，将 `/workspace` 与 `/admin/*` 分离。
- 增加后台布局：侧边导航、顶部当前账号、页面标题、全局提示和退出入口。
- 拆分 `Workspace.vue`，管理后台按页面和业务模块组织，避免继续扩展单个大组件。
- 建立可复用的分页表格、筛选栏、状态标签、确认对话框、空状态和错误提示组件。
- 保持当前轻量视觉风格，不引入大型组件库。
- 优先适配常用桌面宽度；在窄屏下保持查询和基础管理可用，不以手机端复杂批量操作为第一版目标。
- 前端只展示后端返回的允许操作，遇到 401 返回登录页，遇到 403 显示权限不足且不丢失当前筛选条件。

## 6. 实施顺序与验收

### A0：接口契约与控制台骨架

- [ ] 确定页面路由、导航结构、分页响应格式和中文操作名称。
- [ ] 建立 `/admin` 布局、角色路由守卫和无权限页面。
- [ ] 保留原工作台入口与现有功能。

验收：ADMIN/MINISTER 可进入后台；其他角色直接访问时得到明确的无权限结果；刷新任意后台路由仍能正常加载。

### A1：账号管理

- [ ] 完成用户分页查询、角色和状态筛选。
- [ ] 完成新建、资料修改、角色修改、启停和密码重置。
- [ ] 增加首次登录强制改密流程。
- [ ] 补齐角色边界、会话撤销和自我保护测试。

验收：44 个现有账号可分页查看；负责人可以管理账号；部长不能提升权限；被停用、改角色或重置密码的账号旧会话立即失效。

### A2：组织与小组

- [ ] 完成小组统计、详情、成员维护和负责人设置。
- [ ] 显示未分组成员与没有负责人的小组。
- [ ] 补齐跨组权限和未完成任务约束测试。

验收：管理员可从未分组成员建立真实小组关系；组长仍只能管理自己负责的小组；非法跨组操作返回 403。

### A3：任务监管

- [ ] 完成全局筛选、分页、详情和流转记录。
- [ ] 完成负责人调整与验收操作。
- [ ] 增加逾期、并发冲突和数据范围测试。

验收：管理员可以定位任意逾期或待验收任务；无关成员不能通过直接调用接口查看任务详情；并发修改返回 409。

### A4：审计、总览与系统状态

- [ ] 完成总览统计和异常提醒。
- [ ] 完成审计筛选、分页和中文展示。
- [ ] 完成只读系统状态检查。

验收：统计值与数据库抽样查询一致；敏感操作均能在审计中定位；状态页不暴露数据库密码、文件绝对路径或堆栈信息。

### A5：整体回归与本地部署

- [ ] 完成后端权限集成测试、前端组件测试和浏览器完整流程。
- [ ] 验证生产构建继续打包到单一 jar。
- [ ] 更新本地启动、部署和管理员使用说明。

验收：现有登录、成员工作台、任务、评论、附件和通知没有回归；ADMIN 和 MINISTER 分别完成一遍控制台流程；本地部署重启后数据保持不变。

## 7. 暂不纳入第一版

- 手机号、一卡通号等额外个人资料。
- 活动排班、签到、工时和绩效统计。
- Excel 批量导出、批量修改和自动同步 OneDrive。
- 在网页中执行备份、恢复、服务启停或数据库维护。
- 多租户、自定义角色和逐项权限配置。

这些功能待后台控制台稳定、实际小组资料补齐后再评估。
