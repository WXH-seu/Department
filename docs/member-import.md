# 成员账号导入

后端支持从成员 Excel 表一次性创建或同步账号。工作簿首个工作表需包含“学号、姓名、职务”列；列顺序与现有成员表一致。系统只保存这三项中的账号、显示姓名和角色，不保存一卡通号或手机号。

当前职务映射如下：

| Excel 职务 | 系统角色 | 权限范围 |
| --- | --- | --- |
| 负责人 | ADMIN | 系统最高权限，包括账号、角色、全部小组、任务和审计管理 |
| 核心骨干 | LEADER | 所负责小组的人员和任务管理 |
| 志愿者 | MEMBER | 本人任务和所在小组信息 |

成员表没有小组列，因此导入不会自动建立小组或任命具体小组负责人。管理员应在导入后按实际分工建立小组，再把核心骨干设为相应小组的负责人。

## 执行导入

先按部署文档配置数据库。空数据库首次运行时，同时设置 `DEPARTMENT_BOOTSTRAP_*` 创建独立管理员。再为当前 PowerShell 会话设置：

```powershell
$env:DEPARTMENT_MEMBER_IMPORT_FILE='D:\secure\成员信息.xlsx'
$env:DEPARTMENT_MEMBER_IMPORT_CREDENTIALS='D:\secure\成员初始凭据.txt'
```

正常启动后端。导入器会：

1. 校验表头、必填字段、学号唯一性和职务；
2. 删除学号内部空格后作为登录账号；
3. 为新账号生成 18 位随机临时密码并保存 BCrypt 哈希；
4. 对已有非管理员账号同步姓名、启用状态和角色，同时保留原密码；
5. 将新账号的明文临时密码写入指定凭据文件；
6. 为每条同步记录写入审计日志。

凭据文件已存在时导入会拒绝执行，防止覆盖尚未分发的密码。再次同步时请换一个新的输出路径。导入完成后移除两个 `DEPARTMENT_MEMBER_IMPORT_*` 环境变量并重启后端，避免每次启动重复同步。

凭据文件不得提交到 Git。仅把每个人对应的一行发给本人，并要求首次登录后立即修改密码。正式上线前，管理员还应检查角色数量和抽样登录结果。
