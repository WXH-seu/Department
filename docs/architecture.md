# 系统架构设计

## 使用场景

- 用户规模：10～50 人
- 主要网络：校园网
- 校外访问：学校 VPN
- 部署环境：常开的 Windows 主机
- 设计原则：模块化单体、简单部署、数据可备份

## 总体结构

```text
校内浏览器 ───────────────┐
                          ├─ HTTPS 443 ─> Nginx
校外浏览器 ─> 学校 VPN ──┘                 ├─ 前端静态文件
                                           └─ /api ─> Spring Boot 8080
                                                            ├─ MySQL 3306
                                                            └─ 本地附件目录
```

只有 Nginx 的 443 端口面向校园网。Spring Boot 和 MySQL 仅监听本机或由 Windows 防火墙限制为本机访问。

## 后端模块

- `auth`：登录、会话和权限
- `user`：系统账号
- `organization`：人员、小组和职务
- `task`：工作、进度、评论和验收
- `file`：附件上传下载
- `notification`：站内通知
- `audit`：操作日志
- `statistics`：统计查询
- `common`：异常、响应、校验和公共安全逻辑

## 权限模型

采用角色权限与数据范围相结合的方式：

- 系统管理员：系统配置、账号和全部数据
- 部长：全局人员和工作管理
- 组长：本组人员和工作管理
- 部员：查看参与的工作并更新进度
- 访客：只读访问明确公开的数据

后端必须执行权限校验，不能只通过前端隐藏按钮实现。

## 数据与备份

- MySQL 保存结构化业务数据
- Windows 本地目录保存附件
- 每日导出数据库并复制附件
- 备份保留 30 天，并同步到 NAS 或另一台电脑
- 每月执行一次恢复测试

## 网络与安全

- 使用 HTTPS
- 使用 HttpOnly、Secure、SameSite Cookie 保存登录会话
- 启用 CSRF 防护和登录失败限制
- 不向网络开放 8080、3306 和 3389
- 数据库密码通过环境变量或外部生产配置提供
- 记录登录、权限、人员和任务等敏感操作
