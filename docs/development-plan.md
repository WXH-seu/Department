## 实施顺序与验收

1. **P0 工程基线**：验证前后端构建，固定前端依赖，增加持续集成。验收：全新环境可以依照文档构建并运行测试。
2. **P1 登录与权限**：数据库版本迁移；账号、角色、小组基础表；安全初始化管理员；会话登录/注销/当前用户、CSRF 和失败限制。验收：匿名访问业务返回 401，越权返回 403，退出后会话失效，密码不明文存储；角色与数据范围测试通过。
3. **P2 人员组织**：账号停用、人员资料、小组成员和职务管理；分页、搜索、表单校验。验收：管理员和部长管理全局，组长仅管理本组，普通成员不能修改他人资料或权限；停用账号不可继续操作。
4. **P3 任务闭环**：创建、分配、截止日期、进度、提交验收、通过/退回、评论及首页待办。建议状态为待处理→进行中→待验收→已完成，退回进入进行中。验收：参与者只能更新授权任务，验收由管理者执行，状态转换和并发修改受控。
5. **P4 附件、通知与日志**：任务附件授权下载、上传大小与文件名限制；任务分配与验收站内通知；操作审计。验收：不可访问他人附件，不可路径穿越，关键变更可追溯，日志不记录密码与会话信息。
6. **P5 上线验收**：HTTPS、Windows 服务、数据库和附件备份恢复；提供安装配置说明和端到端验收清单。验收：核心操作串联完成，重启数据保留，权限回归通过，备份可恢复。

## 设计约束

- 保留既有 Vue / Spring Boot / MySQL 技术路线，采用模块化单体。
- 真实业务写入数据库，不用前端假数据或内存数据宣称功能完成。
- 后端独立执行权限检查；默认访客不能访问内部数据，公开范围未定义前不提供匿名业务访问。
- 不提交生产密钥、真实成员数据、证书或上传附件。
- 用户尚未指定职务细则与验收人规则，先按架构中的五类角色实现，涉及不可推断的业务决策时询问。
